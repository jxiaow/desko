# 内页三个新架构方向 · 案头不是卡网格

状态：提案（三选一或组合），未落码
日期：2026-10-28
范围：桌面工作区内页（纸 / 墨两套底色）；Web 运行时不在此次范围
基准：1040×670 默认窗口真机页面；数据来自本地 e2e mock
关系：与 [03-sidebar-collapse-and-page-workbar.md](./03-sidebar-collapse-and-page-workbar.md) 的骨架方案（侧栏两态 + 页级工作栏）**并行但不同层** —— 本文改的是**导航模型与对象形态**，03 改的是几何与壳层；[04-interior-material-and-form.md](./04-interior-material-and-form.md) 是材质层的补充（光场、悬停、页名、主钮），本文的三个方向都已内置那四条

> 三个方向都是**真应用注入**跑出来的（DOM 手术 + 真令牌），不是手绘 mock。帧在 `.tmp/directions/`，对比图 `.tmp/directions/compare/directions-compare.png`。

## 0. 先说清为什么上一版不算数

上一版（04 文档的 B 档）被否掉了，理由是对的：它把"把现有卡网格调一调"当成了方案。卡还在、列还在、等宽节奏还在，改的只是底色深浅和字号。

真正的问题是**形态**：13 个等宽白卡铺成三列，每张卡自己是一个房间，行与行之间没有共同的栏。列表页的信息本质是**一条可以竖着扫读的清单**，而卡网格把这个"清单"拆成了 13 个独立对象在读。这是 2026-09-29 那句"行行都是独立胶囊卡"的原话，2026-10-28 换了张皮还在。

所以下面三条，改的是**导航模型**和**对象形态**。

## 1. 甲 · 单列台面（画布即桌面）

**主张**：桌面不是一堆卡片，是**一张纸**，对象是纸上的行。

- 内容区不再收成 900–1120px 阅读列，铺满窗口；纸上放一张白纸（`--panel-bg` + 14px 圆角），对象是纸上的一根根发丝线。
- 收藏：13 个等宽卡 → 一张纸上的 13 行。每行 = 档面 24px / 名称 / 副址 / 行尾分类。行高 52px（现状卡高 88px）。
- 页名从顶栏搬进内容，成为纸上方的一张标签；顶栏只留搜索与动作。
- 小记同理：书写区收成一张纸，条目是纸上的段落（标题 / 正文两行 / 时间），不是一叠白卡。
- 侧栏仍是 56px 图标轨 —— 甲不动导航模型，只动对象形态。

**实测**（`.tmp/directions/A-desk-*.png`）：

| 项 | 现状 | 甲 |
| --- | --- | --- |
| 收藏对象高 | 88px（卡） | 52px（行） |
| 首屏可见条数 | 13 条占 3 屏高 | 13 条占 1 屏高 |
| 对象壳 | 白底 + 圆角 + 透明描边 | 无壳，只有一根发丝线 |
| 页名位置 | 顶栏 | 内容首行（顶栏让位） |

**代价**：搜索、分类筛选、批量操作这些**页级**操作在甲里失去了落点 —— 现在它们挂在顶栏/目录里，甲把它们推给内容区之后，层级关系要重排。

**适合**：以"翻看和扫读"为主的收藏与小记。

## 2. 乙 · 万能检索（不先进模块，直接搜）

**主张**：现在八个模块是**八个入口**，用户要先想"这件事归哪个模块"。Desko 是个人工作台，收藏/小记/文件/验证码是**同一个人的同一堆东西**，为什么要分八个门进去？

- 顶栏换成一根 56px 的巨输入条，居中，placeholder 直接写"搜索收藏、小记、文件、验证码…"。
- 一次输入跨全部模块检索，结果按模块分组（收藏 / 小记 / 文件快捷 / 验证码），每组有自己的小标题。
- 结果行：模块名（44px 灰字）+ 主名 + 副信息。方向键选、⏎ 打开。
- 底部一行键位提示。
- 这是**续锁页的语言**：锁页已经是一根输入条 + 呼吸光场 + 衬线题词了 —— 解锁后立刻换成同一根输入条，用户不需要重新学。

**实测**（`.tmp/directions/B-omni-*.png`）：跨四类模块一次出结果，视觉上最接近锁页，也最不像"后台"。

**代价**：这一条**动得最深**。
- 它把"模块"从导航降级为"结果分组"，八个模块的独立页面（Codex 用量图表、内网穿透的服务表、局域网传输的传输列表）**不能全靠检索承载** —— 那些是持续运行状态，需要仪表式的常驻视图。
- 合理形态是**双层**：检索层作为跨模块的快速入口（⌘K），模块页面保留给重状态模块。
- 输入框拿走顶栏后，原顶栏的页内动作（新增条目、目录开关、锁定、窗控）需要重新安置。

**适合**：收藏、小记、文件、验证码这类"找东西"的模块。

## 3. 丙 · 主从双栏（对象有本体）

**主张**：收藏条目不是一行字，是**一个有账号、有密码、有备注的对象**。现在的做法是点开弹窗看详情 —— 弹窗把对象打断，且一次只能看一个。

- 左侧 336px 列表栏：条目按行排，选中项有实底。
- 右侧常驻详情栏：档面 56px、名称 24px、网址、账号 / 密码 / 分类三行字段（等宽字体 + 每行一个复制钮）、备注、动作行（打开 / 复制网址 / 更多）。
- 密码这类密文**在这条架构下第一次有正经的展示位** —— 现状是列表里一枚 13px 锁标，点开弹窗才知道有没有密码。
- 列表栏背景比画布深半档（`color-mix(text 2%)`），与右侧形成明确的"两栏"关系。

**实测**（`.tmp/directions/C-split-*.png`）：纸墨两套都成立，墨底尤其好 —— 详情栏的字段块在近黑底上靠发丝边分层，不需要投影。

**代价**：
- 336px 列表栏是**常驻**的，1040 窗下正文只剩 ~700px。收藏条目多的时候左侧也会需要自己的滚动。
- 详情栏与现有**右侧目录**（`#workspace-directory`）位置冲突 —— 03 文档刚提议把目录退役，这里是同一个位置的另一种用法。
- 批量操作在双栏下要重新设计（现在选中即多选）。

**适合**：收藏（有凭据、有备注）、Codex 账号（额度、会话、环境）。

## 4. 三条横向对比

| | 甲 单列台面 | 乙 万能检索 | 丙 主从双栏 |
| --- | --- | --- | --- |
| 改什么 | 对象形态 | 导航模型 | 信息层级 |
| 动多深 | 中（模板 + 样式） | 深（路由与状态重构） | 中（模板 + 布局） |
| 对锁页的延续 | 画布给光 | 同一根输入条 | 无直接延续 |
| 现状痛点解到几成 | 胶囊海（形态） | 模块割裂（导航） | 弹窗打断 + 密文无位 |
| 03 文档冲突 | 无（几何层并行） | 部分（页级工作栏要重排） | 有（右侧目录位置） |
| 丢掉什么 | 页级操作的落点 | 重状态模块的仪表视图 | 宽窗的长阅读列 |

## 5. 我的推荐

**先落甲与丙，乙只做跨模块的 ⌘K 入口层（不做成替代全部模块页）。**

理由：
1. 甲和丙是**形态层**改动，能独立验证，不必等路由重构。
2. 甲治的是那句"普通笨重"的原话（胶囊海），丙治的是"点开弹窗才知道有没有密码"这个真实痛点。两条都不与 03 文档打架（丙只与目录位置有重叠，可把目录退役后直接复用那块地）。
3. 乙最有特色，但它要求把八个模块里"重状态"的那几个（Codex 用量、内网穿透、局域网传输）单独拎出来继续做仪表视图 —— 这是**另一个项目的工作量**，不适合塞进这一轮。而且 ⌘K 检索层可以作为薄薄一层加在任何架构之上。

**顺序**：甲（收藏 + 小记先落，验证码和 Codex 不动）→ 丙（收藏接详情栏，目录退役后复用）→ 乙（作为横切层加在最后）。

## 7. 验收（以甲 + 丙为例）

1. 1040×670 纸 / 墨：收藏 13 条首屏可见 13 条，行高 52，无卡底 / 无圆角 / 无描边，行间 1px `--border`。
2. 甲档：页名在内容首行，顶栏不再重复；搜索与新增动作在顶栏原位可用。
3. 丙档：列表栏 336px，详情栏常驻；选中切换条目时详情内容随之变；密码字段有复制钮；列表栏与详情栏之间 1px `--border`。
4. 墨底详情栏字段块在近黑底上按项目基线（正文 ≥ 4.5:1、12px 小字 ≥ 5.8:1）复核。
5. 验证码的三列网格与 Codex 的仪表视图在甲丙两档下**保持不变**。
6. `node scripts/check-theme-coverage.mjs` 不新增违例（96 槽契约不动）。
7. `npx vue-tsc --noEmit`、`npx vitest run`、`npx playwright test` 全绿。

## 8. 不做 / 否决

- 不做"双壳"（外框 + 内页两套壳）：2026-10-26 已整轮回撤，本文不重提。
- 不给内页加衬线正文：锁页的衬线是题词独白。
- 不给内页加常驻动效：光场是静态材质。
- 不给卡面加回描边或投影：层次由底色阶梯承担。
- 不把检索层做成唯一入口：重状态模块需要仪表视图。
- 不动小记的便签内容卡（甲档改的是纸面段落，密级富文本的编辑态另算）。
