# 浏览器授权领取与主域名引导

## 问题与现场证据

浏览器授权会由 cloudflared 写入本机凭据。本次现场检查发现凭据已写入当前档案的 `tunnel/login-home/.cloudflared/cert.pem`，但正式的 `tunnel/cf/cert.pem` 不在。此前授权登记死锁阻止了领取；应用重启后，又因为没有在途登录句柄而不再领取这份暂存凭据，页面因此继续显示未授权。

另一处缺口是没有主域名查询。原界面只知道凭据文件存在，添加服务要求填写完整主机名，用户不知道浏览器所选主域名时无法继续。使用现场暂存凭据调用 Cloudflare 的只读 zone 查询已成功，证实可读取所选域名。

## 实现

授权状态允许领取当前档案专用登录目录的暂存凭据，即使登录进程句柄已因重启丢失；仍不领取用户外部的 `~/.cloudflared`。发起登录前先检查可领取的既有凭据。授权状态查询与撤销共用进程编排锁，撤销同时删除正式与暂存凭据，删除失败返回错误，防止下一轮状态读取恢复已撤销授权。

新增 `tunnel_authorized_domain` 后台命令：从 `ARGO TUNNEL TOKEN` PEM 块解析 `zoneID` 和 `apiToken`，以 Bearer 凭据请求 `GET https://api.cloudflare.com/client/v4/zones/{zoneID}`，只返回 `name/status`。只读取本次授权所选的 zone，不把账号下其他域名误当成已获得 DNS 操作授权的域名。凭据不返回前端，不落域名缓存文件；请求超时 15 秒，不跟随重定向，权限与网络失败分别给出可重试提示。

前端在识别授权后自动查询一次，与每三秒的本地轮询分开。授权行和收起摘要展示主域名。添加服务显示所选主域名，用户只填 `files` 这样的前缀，立即预览 `https://files.example.com`；保存仍使用完整主机名的既有命令契约。保留显式手动输入完整域名的入口，以支持旧服务编辑。尚未读取主域名、前缀不合法或域名未启用时，自动拼接模式禁止保存并解释原因。

撤销授权时清理前端域名缓存，并丢弃旧请求晚到的结果。域名查询失败不撤回本机授权，接入准备与服务弹窗均提供重试入口。已有服务编辑时自动拆分匹配主域名的地址，异步查询不覆盖正在填写的服务内容。

## 验证与使用

Rust 回归覆盖重启领取、撤销后不恢复、PEM 解析、查询目标与授权头、返回域名校验、权限错误和凭据不泄露。Vue 回归覆盖授权自动读取、缓存与重试、晚到结果、前缀拼接、旧服务编辑和保存限制。浏览器回归覆盖自动显示域名、生成地址、失败重试、授权后刷新并用主密码重新解锁。

使用顺序：先启动需要开放的本机 HTTP 服务；在接入准备中建立隧道；添加服务，填写前缀和本机端口；点击「应用」登记 DNS，再启动隧道。局域网传输可通过「获取端口」取正在监听的端口，公网访问还需设置服务口令。

参考：[cloudflared 授权凭据格式](https://github.com/cloudflare/cloudflared/blob/master/credentials/origin_cert.go)、[Cloudflare Zone Details](https://developers.cloudflare.com/api/resources/zones/methods/get/)。
