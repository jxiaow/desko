## 一句话

推翻「每条目标都配一行表格」的前提：**正常的不配占行**。异常项升格成完整卡并常驻展开入口，直连可用的目标收成一行 chip；页面从「一张表 + 一行小账」变成「概览 → 要处理的事 → 已好的名单」三层。

## 分区判据（前端派生，与后端 `needsApply` 同判据不另算）

| 归属 | 判据 | 说明 |
|---|---|---|
| 需要处理 | `applyState === 'failed'` 或 `stale` 或 `verdict === 'unreachable'` | 需检查档，排在前 |
| 需要处理 | `needsApply(t)`（hostsOnly / needRoute 且未 applied） | 待配置档，排在后 |
| 需要处理 | `verdict === 'egressUnknown'` | 第五档不给写入建议，但要人看一眼，归需检查 |
| 直连可用 | 其余（`directOk` 且无上述异常） | 收 chip |

卡上的状态旗沿用现有 `flagsOf` 全套（需检查 / 固定地址不可用 / 地址可能变化 / 已配置），一枚不砍，只是从「行上只留最高一颗」改为**异常卡上全量常驻**——异常项本来就少了，不必再省。

## 各区规格

### 1. 概览 hero（取代小账行）

一张浮岛卡（`--panel-bg` + 12 圆角 + `--shadow-card`），单行三段：

- 左：大数字 `可用数 / 总数`（34px/700，取 `--success` 档；有异常时数字仍绿，异常数不重复显示——分区头自带条数）+ 细字 sub 行
- sub 行：`出口：以太网 N · WLAN N · 按网段路由 N · hosts 管理记录 N 条`。接口计数按 `interfaceName` 分组，网段（`kind === 'cidr'`）单列一档。`hostsError` 时整行改口为「无法读取本功能管理的 hosts 记录 · 原因」，沿用现有小账判据与文案
- 右：动作区 = 「配置直连 N」（N>0 才出，全局 `btn-primary` 档不变）+「检查全部」（`btn-secondary`）+ 一颗 `⋯`（低频项，已定 Q1）

### 2. 需要处理

- 区头：`需要处理` + 条数；**0 条时整区不出**
- 每条一张浮岛卡，64px 档（对齐全站 `rcard-row` 行卡体系，替代 48px 表格行）：
  - 首行：名称（`hostOf` 同规则）+ 判定 badge + 状态旗 badges 全量
  - 次行：地址（等宽）· 出口 · 一句结论（`faceNote` 同规则：与首行判定 badge 同义的不念——等于或起头于判定标签、以及 `directOk`/`egressUnknown` 两档一律置空）
  - 右端：`重新探测`（action-btn，28px 档）+ `⋯`（移出清单）
- 卡面点击 = 就地展开（沿用现有 `.row-card` 凹底：结论全文、网关、探测时间、改原文 + 「探测并保存修改」），展开语义与现在完全一致，只是入口从行首箭头变成整卡。展开档走 `rowNote`：在 `faceNote` 之上再补一句落盘状态（写失败 / 待配置 / 已配置），结论为空时整段不出
- 顺序：需检查在前、待配置在后；同级按名称

### 3. 直连可用

- 区头：`直连可用` + 条数 + `上次检查 <月/日 时:分>`（取该区 `max(checkedAt)`）+ 右端筛选输入（140px 档，只筛 chip，已定 Q4）
- 目标收成 chip 行（28px 胶囊、绿点 + 名称、按名称排序、自然 wrap）
- chip 点击 → 详情弹窗（复用 `.dialog` 520px 壳，内容 = 现展开卡里那一套：结论（与展开档同一句规则，空则不出）+ facts + 改原文 + 重新探测 + 移出清单）
- chip 不给 hover 动作（防误点，动作全在弹窗内）

### 4. 页脚注与空态

- `.page-note` 保留原文案
- 清单整体为空：沿用现有 `empty-state` 卡
- 全部直连可用：「需要处理」区不出，hero 大数字即 `N / N`，chip 区就是全量——页面自然收成一屏干净
- 一条直连可用都没有：「直连可用」区整段不出（区头 + 筛选），那笔账由 hero 的 `0 / N` 说，不留一行空区头

### 5. 不动的部分

探测区、探测结论弹窗、落盘计划/结果/撤销弹窗、UAC 等待态、重验进度与停止、互斥闸门（`operationBusy`）、`pageHead` 标题栏计数、窄窗换行档。

## 已定（2026-10-14 逐项拍板）

- **Q1 低频动作去向**：「复制直连清单」「撤销上次配置」收进 hero 右端的 `⋯` 菜单；页面上只常驻「配置直连 N」和「检查全部」两颗。
- **Q2 chip 点击行为**：开详情弹窗（`.dialog` 520px 壳，内容 = 结论全文 + facts + 改原文 + 重新探测 + 移出清单）。chip 区保持一行高。
- **Q3 「需要处理」分区粒度**：一段混排，不再拆「待配置 / 需检查」两段小标题；性质由卡上判定 badge 说明，排序保证需检查在前。
- **Q4 筛选作用域**：筛选框只筛「直连可用」的 chip，住该区区头右端；异常卡不参与筛选。

## 重新探测后的处理引导（2026-10-14）

结论弹窗先说明当前问题，再给出下一步。缺路由时明确区分「目标可连接」与「出口已绕过代理」，不重复显示两次「需配置路由」。源地址、网关、DNS 和 hosts 等证据收进默认折叠的「技术详情」；IP 与网段不显示不适用的 DNS、hosts 行。

已保存且需配置的目标直接提供「配置直连」，进入既有配置确认流程；方案生成失败保留探测结果。此入口仍使用清单中的批量待配置目标，多项时按钮与说明明确显示数量，确认前列出完整方案。系统写入与管理员授权沿用原流程。

引导同时说明代理客户端的直连规则仍需用户配置，提供「复制直连目标」，复制域名、IP 或网段本身，不附带服务端口。系统配置后自动复验；代理规则调整后可以再次探测。不可达和出口未知结果提供显式重试入口。

验证：新增回归覆盖 IP 重探后进入配置确认、方案失败保留结果、复制 IP 不带端口，以及批量方案范围提示。全量前端单测 392 项、网络直连浏览器测试 46 项、类型检查与安装包构建通过；已核对 `10.0.0.243 / 0dcloud` 示例截图。
