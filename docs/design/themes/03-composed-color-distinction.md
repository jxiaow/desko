# 主题与氛围的合成色区分

## 问题

设置中的色点不同，叠到实际画布上却容易趋同。原紫罗主色偏蓝；氛围反复使用同一低彩度强调色，浮层再覆盖 60% 中性色。纸与雪、墨与岩的底色差也被柔光削弱。

以 1040 × 670 的同一主界面、15 处空白画布像素比较，原墨蓝与紫罗的平均 CIE76 色差只有 0.92–0.98。仅断言 CSS token 不同无法发现这个问题。

## 配色调整

| 轴 | 调整 |
| --- | --- |
| 纸 | 象牙白内容面、暖灰画布；描边与悬停同步调整 |
| 雪 | 保留中性瓷白与灰色明度台阶 |
| 墨 | 保留暖色深墨画布 |
| 岩 | 抬升为蓝灰板岩；文字、描边、悬停与文件占位色同步提亮 |
| 强调色 | 墨蓝、玉石青绿、赭橙、紫罗、玫红；主色及 hover、active、soft、品牌渐变等整族同步调整 |

仍为四种底色 × 五种强调色。底色 96 槽、按极性覆盖的强调色 17 槽不变；四套底色的缺省墨蓝与对应覆盖层一致。主题 ID、存储键和旧 ID 迁移不变。

## 氛围合成

`materials.css` 为每种强调色定义主光、辅光两个装饰色，控件色继续负责文字与交互对比。背景以透明度控制强度，不再直接把控件主色反复稀释。

- 主界面：两处 24% 径向柔光，去掉覆盖色相的中性光层。
- 浮层：中性色覆盖从 60% 降至 25%，仍以当前卡面作为实底。
- 锁屏：主光 24%、辅光 18%，保留较弱的中性提亮与现有呼吸动画。
- 设置缩略图：在自身 `.theme-scope` 中重算相同配方，按卡片尺寸缩放。
- 内容卡片和输入区域继续使用实底；关闭氛围恢复纯底，系统减少动态效果时停止装饰动画。

## 验证

- `scripts/check-theme-coverage.mjs`：四套底色键集、十组强调色覆盖和材质边界检查。
- `e2e/specs/theme.spec.ts`、`materials.spec.ts`：切换、持久化、迁移、缩略图一致性、氛围开关和减少动态效果。
- `e2e/specs/theme-composition.spec.ts`：通过设置切换全部 20 组，读取实际截图的 15 处画布像素。浅色同底不同强调色平均色差须大于 2，深色须大于 2.5；同强调色纸/雪须大于 3，墨/岩须大于 7。门槛用于阻止本次趋同问题回归，不替代视觉检查。
- 合成测试同时检查画布辅助文字与主按钮普通、悬停、按下三态的对比度均不低于 4.5。
- 逐组查看锁屏、主界面、设置，以及氛围关闭状态的截图；检查修改后纸/岩代码文字与状态色对比。

颜色数值以 `global.css`、`materials.css` 为准，自动导出的 `01-token-inventory.md` 与实现同步。
