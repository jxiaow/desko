# Codex 会话档：单行密度与用量摘要（2026-10-20 修订）

当前实现：**会话分组首次全部收起，搜索词在时显示命中行；会话保留 44px 单行，完整用量放在展开详情；顶部统计采用紧凑两行摘要，桌面目标高度 84–96px**。会话和用量的长段解释统一收进「统计说明」。不改后端、命令注册、统计口径和预取策略。历史记录保留，当前规格以第 3 节及最新用户修订为准。

## 1. 背景：为什么不是「健康度反转」

直连页（`docs/design/bypass/03-bypass-health-inversion.md`）的反转成立是因为好目标不该占行；会话页每条记录地位平等，没有可收编的一类。以下四项是 2026-10-14 的历史问题，不代表当前仍全部存在：

1. **首屏全是壳**：`CodexSessionsPanel.vue:104` `openKeys` 初值为空集，进档只见分组卡不见一条会话，必须先点一组。上游官方面板同样全折叠（`07-session-list-port.md` §2.3），但上游侧栏语境下一屏十几组可扫；desko 是整页，首屏信息量过低。
2. **搜索结果被折叠态吞掉**：搜索命中后各组仍折叠（`openKeys` 不随搜索变），用户看到组卡条数变了却要逐组点开才能看到命中行。
3. **行密度服务于次任务**：每条会话 56px 双行（`:519` `.sess-row`），L2 整行给了 token 两位读数；这一页的主任务是按标题/正文找会话，token 是次任务，占了一半行高。
4. **小账卡方言落单**：顶部 44px `.sess-sum` 是自定义细条，与直连页 hero（大数字 + 细字账行 + 浮岛壳）不同语言。

## 3. 规格

### 3.1 展开态规则

- **首次收起**：`sessionOpenGroups` 初始为空，取得列表、后台刷新或迟到统计都不自动展开分组；不再设置播种闸门。
- **搜索全展开**：`sessionQuery` 有词时，渲染层视为全部组展开，不回写 `sessionOpenGroups`；清空搜索词回到用户自己的展开态。搜索中的组头仍可点，点了就修改保存的展开态，清空词后生效。
- **切档保留**：`sessionOpenGroups`、`sessionOpenId` 同住 `codexState`，只保存在内存。切去账号、用量、回收站再回来不丢；锁屏清理会话时一并复位为全部收起。
- 行内展开规则不变：再点别行即换，折叠组时清掉属于该组的展开行。

### 3.2 会话行 44px 单行

- 行 = 标题 + `sessionKind` 徽标（子代理/外部）+ 右端 `MM-DD HH:mm`。没有标题时显示完整会话 ID，空间不足允许 ID 换行。
- **Token 不上行**：标题悬停只显示完整标题或完整 ID，不弹多行统计；展开详情保留净输入、缓存命中、缓存写入、输出、其中推理、官方累计六口径，以及请求数、估算金额。
- 行高至少 44px，hover 使用 `--hover`，26px 缩进与组内细线分行不变；保留 `aria-expanded` 和说明展开动作的 `aria-label`。
- 预取策略不变：进档全量预取，摘要总账、组头合计与展开详情共用统计。

### 3.3 用量摘要

- 壳：沿用共享 `.rcard` 表面、边框与阴影变量，12px 圆角，避免局部样式绕过工作区的轻量卡片规则。
- 第一行左侧：**累计 Token 总量**（`compact(allSum.total)`，24px/600，取 `--text` 主色）+ 细字 label「累计 Token」。
- 第一行右侧：估算金额（USD）与请求数，保持各自标签与数值完整显示。
- sub 行：`N 个项目 · M 条会话 · 净输入 X · 输出 Y · 缓存命中 Z`（`--text-muted` 档；X/Y/Z 用现 `compact` 口径）。
- **无动作**：「刷新」留在 `.page-bar`，摘要不放按钮。
- 桌面两行布局，目标高度 84–96px；窄于 600px 时按总量、金额与请求数、细字账行依次排列，允许增高，不隐藏字段。
- 统计未完成：显示「统计中 k / M」，不展示不完整的金额与分项合计；保留摘要空间。大数字悬停显示精确 Token 总数，卡片悬停显示原有汇总说明。
- 会话页和用量页共用默认收起的「统计说明」，点击或键盘展开后可查看目录范围、缓存与推理口径、请求去重及 API 估价说明。移除常驻长段解释和重复副标题，保留所有关键数字与必要标签。

## 5. 当前结论（2026-10-20 修订）

- **D1 默认收起** → 首次进入不展开；搜索词在时渲染层全展开，清空回用户态，刷新不自动展开。

## 8. 历史执行结果（2026-10-14）

1–3 全绿：`vue-tsc` 0 error；`vitest` 370/370；`codex.spec.ts` 57/57（含新增「搜索命中即展开」「切档再回来展开态不丢」两条，首屏那条按播种语义重写）；全量 e2e 325/325；`codex-shots.mjs` 21 帧全部本次新拍。

落地时相对本计划的三处收紧，都写进代码不留在口头：

- 播种要一枚闸门：`sessionGroupsSeeded` 与两份展开态同住 `codexState`，否则面板卸挂重挂会重新播种，把用户刚折叠掉的组再打开。
- 组展开的 e2e 入口统一走 `expandGroup(page, name)`（`aria-expanded` 已是 `true` 就不再点）：播种之后，老用例里那句「点组头展开」有一半变成了「点组头折叠」。
- 行定位改用 `data-sid`：`.sess-row` 的 first 不再等价于某一组的第一行，播种组会插队。

顺带修掉三处与本轮无关的陈旧出图定位器（并行会话在途改动撞上来的，不修则整条截图流水线红）：账号 ⋯ 菜单的编辑项已按凭据类型分档（`名称与备注` / `账号与密钥`）、用量默认档已从「近 30 天」改到「今天」（柱状帧需先切档）、设置页签改名「Codex」。
