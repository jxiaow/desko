# Codex 会话档：单行密度 + 展开播种 + 用量 hero（待拍板 2026-10-14）

一句话方案：会话档三条纯前端收紧——**进档默认展开最近一组、搜索词在时全部展开；会话行从 56px 双行收成 40px 单行（token 出悬停与展开档）；顶部 44px 小账卡升格为与直连页同语言的 hero**。零后端改动，命令面不动（在册 63），数据流与预取策略不变。

## 1. 背景：为什么不是「健康度反转」

直连页（`docs/design/bypass/03-bypass-health-inversion.md`）的反转成立是因为好目标不该占行；会话页每条记录地位平等，没有可收编的一类。但这页有三个自己的毛病（2026-10-14 对照现状代码核实）：

1. **首屏全是壳**：`CodexSessionsPanel.vue:104` `openKeys` 初值为空集，进档只见分组卡不见一条会话，必须先点一组。上游官方面板同样全折叠（`07-session-list-port.md` §2.3），但上游侧栏语境下一屏十几组可扫；desko 是整页，首屏信息量过低。
2. **搜索结果被折叠态吞掉**：搜索命中后各组仍折叠（`openKeys` 不随搜索变），用户看到组卡条数变了却要逐组点开才能看到命中行。
3. **行密度服务于次任务**：每条会话 56px 双行（`:519` `.sess-row`），L2 整行给了 token 两位读数；这一页的主任务是按标题/正文找会话，token 是次任务，占了一半行高。
4. **小账卡方言落单**：顶部 44px `.sess-sum` 是自定义细条，与直连页 hero（大数字 + 细字账行 + 浮岛壳）不同语言。

## 2. 范围

## 3. 规格

### 3.1 展开态规则

- **进档播种**：列表首次就绪时把 `openKeys` 播种为「最近活动」第一组（`groups[0]`，排序规则不变）。只播一次：用户之后折叠它，本轮会话内不再自动开。
- **搜索全展开**：`sessionQuery` 有词时，渲染层视为全部组展开（纯渲染规则，不回写 `openKeys`）；清空搜索词回到用户自己的展开态。搜索中的组头仍可点，点了就改 `openKeys`，清空词后生效。
- **切档保留**：`openKeys` 与 `openSessionId` 从组件 `ref` 提升到 `codexState`（内存级会话状态，不落盘、重启不记）。现状组件被 `v-if` 卸挂即丢态，切去「用量」再回来要重新翻——提升后账号/会话/用量/回收站之间随便切不丢。
- 行内展开（`openSessionId`）规则不变：同组再点别行即换，折叠组时清掉属于该组的展开行（现逻辑 `:107-118` 原样上移）。

### 3.2 会话行 40px 单行

- 行 = 单行：标题（无标题给 `01a12582…` 短 ID，现 `idAsTitle` 规则不变）+ `sessionKind` badge（子代理/外部）+ 右端 `更新 MM-DD HH:mm`。
- **token 不上行**：`.sess-l2` 与占位灰线 `.tok-ph` 整段退役，`tokenText` 删。token 的去处：
  - 悬停：行的 `title` = 完整标题（无标题给完整会话 ID），token 有数时换行拼上现 `tokenTip` 那句五口径；没数就只剩标题。
  - 展开档：`.sess-facts` 六口径原样，一个字不动。
- 行高 40px、hover 吃 `--hover`、26px 缩进与组内细线分行不变；`aria-expanded`、凹底展开、行点击语义不变。
- 预取策略不变（进档全量预取，`codexState.ts:385/418`）：hero 总账、组头合计、行悬停都要这份数，没有理由改节奏。

### 3.3 用量 hero

- 壳：浮岛卡（`--panel-bg` + 12 圆角 + `--shadow-card`），与直连页 hero 同壳不同内容。
- 左：大数字 = **累计 Token 总量**（`compact(allSum.total)`，34px/700，取 `--text` 主色——这是账目不是健康判定，不吃 `--success`）+ 细字 label「累计 Token」。
- sub 行：`N 个项目 · M 条会话 · 净输入 X · 输出 Y · 缓存命中 Z`（`--text-muted` 档；X/Y/Z 用现 `compact` 口径）。
- 右：**无动作**。「刷新」住 `.page-bar` 不动，hero 不放按钮——这页没有批量动作可给。
- 统计未完成：大数字位改显示「统计中 k / M 条」（沿用现 `sum-label` 文案口径），sub 行不出；全量就绪才出账。`title` 悬停给全精度 `sumText`（现规则平移）。
- 现 44px `.sess-sum` 整卡退役，样式块随之删。

## 5. 拍板结论（2026-10-14，四项已定）

- **D1 展开播种** → 进档默认展开「最近活动」第一组，只播一次；搜索词在时渲染层全展开，清空回用户态。
- **D2 单行 40px** → token 让位给检索密度，只留悬停 `title` 与展开档六口径。代价：行上看不到用量一览，那本来就是「用量」页签的职责。
- **D3 hero = 累计 Token 大数字** → 主色不吃 `--success`，右侧无动作，刷新留 `.page-bar`。
- **D4 展开态提升 `codexState`** → 内存级，切档不丢、重启不记。

## 6. 风险

- 无后端、无数据面、无持久化变化，风险面集中在 e2e 断言迁移（`codex.spec.ts` 约 6 处会话断言跟着改语义，不改行为判据）。

落地时相对本计划的三处收紧，都写进代码不留在口头：

- 播种要一枚闸门：`sessionGroupsSeeded` 与两份展开态同住 `codexState`，否则面板卸挂重挂会重新播种，把用户刚折叠掉的组再打开。
- 组展开的 e2e 入口统一走 `expandGroup(page, name)`（`aria-expanded` 已是 `true` 就不再点）：播种之后，老用例里那句「点组头展开」有一半变成了「点组头折叠」。
- 行定位改用 `data-sid`：`.sess-row` 的 first 不再等价于某一组的第一行，播种组会插队。

顺带修掉三处与本轮无关的陈旧出图定位器（并行会话在途改动撞上来的，不修则整条截图流水线红）：账号 ⋯ 菜单的编辑项已按凭据类型分档（`名称与备注` / `账号与密钥`）、用量默认档已从「近 30 天」改到「今天」（柱状帧需先切档）、设置页签改名「Codex」。
