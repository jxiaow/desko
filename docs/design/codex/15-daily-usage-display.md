# Codex 当天小时趋势与每日明细（2026-10-13）

用户指出用量页面不直观、缺少当天统计。原来默认近 30 天，只有近 7 天/近 30 天/全部；总数的统计范围不明确，按日数字主要依靠悬停柱图读取。

## 展示与范围

- 增加“今天”，首次进入默认查看今日用量；显示日期及实际本地起点。通常是 00:00，零点跳时的日期使用首个有效时刻。
- 汇总突出总 Token，下方直接展示净输入、缓存命中、输出，以及轮次、会话数、输出中的推理数量和更新时间。
- 无记录时保留明确的零统计和空态，仍可以切换范围查看历史。
- 近 7 天/近 30 天按包含今天的 7/30 个本地自然日计算，修复此前实际覆盖 8/31 个日期的问题。日期回退使用日历操作，跨夏令时仍保持本地零点。
- 历史柱高表示总 Token，包含净输入、缓存命中与输出；增加每日明细表，按日期倒序直接读取总数和构成。“全部”仍汇总全部记录，柱图显示截至最后一条记录的连续 30 个自然日，缺失日留空；明细显示最近 30 个有记录的日期。
- 今天使用按小时的折线与面积图，突出高峰时段；鼠标或键盘选择小时点可直接读取该小时的 Token、轮次和构成，当前小时明确标为累计中。已过的空小时按零显示，未来时段留空。
- 当天构成使用横向堆叠条，直接展示净输入、缓存命中、输出的数量与占比；历史范围继续保留按天柱图和每日明细。
- 按模型统计跟随所选范围，今日模型数值不会混入昨天。

## 数据与生命周期

沿用 `codex_query_session_usage` 以及 Rust 按本地事件时间聚合累计快照差值的实现，在同一份过滤后的事件上新增 `byHour`。小时桶从当天首个有效时刻按实际经过的 3600 秒划分，key 为 Unix 秒；回拨的重复小时不合并，前端用 UTC 偏移区分同名时段。没有新增数据库、注册命令或计价模型。输入包含缓存命中，推理已计入输出；回收站里的会话不参与统计。

查询固定请求开始时的截止上界（秒精度、右开边界），排除未来时间戳，并把该时刻作为界面的“截至/更新于”时间。汇总、模型、按日和小时曲线共用截止口径，扫描结束时间不能冒充数据截止时间。

前端在扫描期间切换范围时串行补查最后选择的范围，过时结果或过时错误不能覆盖新范围。切换时清掉旧汇总，避免标题变为“今天”但数字仍是月统计。

扫描跨午夜时同时核对范围和实际时间起点，窗口变化后重新查询。用量面在下一本地零点自动刷新，离开页面清理定时器；跨日重进页面也核对缓存日期和窗口起点。应用锁定时继续沿用解锁代次检查，迟到结果不能重新填入缓存。

## 2026-10-15 可读性调整

- 会话总量、项目合计、展开明细，以及用量汇总、图表读数、每日表格、模型统计统一使用中文“万 / 亿”，最多保留两位小数。例如 `65,120 → 6.51万`；不足一万使用千分位。完整计数保留在数字提示和图表可访问名称中，统计口径不变。

## 2026-10-15 金额与请求数

- 会话汇总、项目合计和会话展开明细新增请求数与估算金额；用量汇总、每日明细、模型统计和图表提示采用相同字段。“轮次”统一改为“次请求”，避免与用户对话轮数混淆。
- 会话请求数与金额复用用量扫描的非零累计增量事件和内存缓存；相同累计快照及仅包含额度的记录不重复计数。时间窗口仍在差分完成后过滤。
- 参考 [cockpit-tools 标准价格与计价函数](https://github.com/jlcodes99/cockpit-tools/blob/main/src-tauri/src/modules/codex_local_access_routing_pricing.rs) 及其历史模型价格表，提取 21 个模型的标准 USD / 百万 Token 单价到 `src-tauri/codex-core/resources/codex_session_pricing.json`。数组依次为净输入、缓存输入、输出，随代码维护；没有引入网关或计费服务。
- 金额 = `((输入 − 缓存) × 输入单价 + 缓存 × 缓存单价 + 输出 × 输出单价) / 1,000,000`。缓存上限为输入数量；推理包含在输出中，不再收费一次。按事件模型计价后求和，兼容模型命名空间及日期版本。
- 金额明确标注为标准 API 价格估算，不代表订阅实际扣费，也不包含 Fast、长上下文等特殊倍率。混有未定价模型的汇总金额为 `null`，显示“未定价”；已知模型的分项金额仍然保留。没有记录的金额为 `$0.00`，极小非零金额显示 `<$0.0001`。
- 验证：70 项相关前端单测、32 项 Rust 会话测试、79 项浏览器回归及生产构建通过。覆盖模型切换、缓存上限、重复快照、时间窗口、未知价格、零用量和 800px / 1235px 布局。原生测试使用临时合成会话，浏览器使用隔离假后端。
- 预览：`.tmp/codex-billing/usage-800.png`、`usage-1235.png`、`sessions-800.png`、`sessions-1235.png`。

## 2026-10-15 金额偏高校正

IDE 续接历史会话时，新文件首条 `total_token_usage` 可能包含历史累计，而 `last_token_usage` 仅包含这次请求。此前首条累计没有前置基线，整份历史因此被当作新增用量，并按当前模型再次计价。本机 141 份会话中发现两份此类记录，其余非零累计差值与本次用量一致。

扫描首条有效快照时，优先采用有效的 `last_token_usage`，同时将原始累计保存为后续差分基线；后续重复快照和额度通知继续跳过。首条本次用量为零时只建立基线；旧记录缺少有效本次用量时保留累计口径。会话列表的六项 Token 统计、请求数和金额全部汇总相同增量事件，与按日、按小时和按模型的用量一致，不再读取末条历史累计作为显示总量。

同一会话 ID 的多个分页文件统一累加，会话数按 ID 去重，扫描文件数仍按实际文件计数；此前会话列表只返回首个匹配文件的统计。合成回归同时检查分段前后的会话合计、模型和时间桶金额一致。

已核对 [OpenAI API 价格](https://developers.openai.com/api/docs/pricing) 与 [缓存计费说明](https://developers.openai.com/api/docs/guides/prompt-caching)。本次修正历史用量重复计算，保留现有标准 API 单价估算口径。回归覆盖带历史基线的首条快照、重复快照、模型切换、时间窗口、零用量和旧格式回退。

验证：33 项 Rust 会话回归通过；独立扫描两条续接会话的三份分段文件，再调用原生统计接口逐项核对 Token、请求数与金额。全部 141 份本地记录的按日、按小时和按模型金额、Token、请求数合计一致；核对过程只读取本地数据。
