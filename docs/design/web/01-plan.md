# Web 端（远程访问）设计方案

日期：2026-09-26　状态：历史草案

> 2026-10-15 实施更新：已提供共用桌面主密码的本机 / 局域网 Web 服务，并扩展至七个模块。当前行为以 [Web 访问说明](../../web-access.md) 和源码为准；以下保留最初方案记录。

## 1. 形态定位

desko.exe 本机照常运行、数据不出本机。App 内嵌一个 axum HTTP 服务，只绑 `127.0.0.1:端口`，由用户自己的穿透工具（frp/cpolar 等，穿透层不带认证）映射到域名。手机/外地浏览器访问该域名，即是"远程操作本机 desko"。

不新增独立服务端，不重写前端：复用现有 Vue 五视图与 Rust 命令层。

进入 web 的模块：**收藏、小记、验证码、文件**（局域网传输、备份/云同步管理不进 web）。

## 2. 传输层：单 RPC 端点 + 命令白名单

桌面端现在前端直接 `invoke('命令名', args)`。Web 端在 `src/services/api/` 之下抽一层 transport：

- 桌面环境：仍走 tauri invoke（现状不变）。
- 浏览器环境：`POST /api/rpc`，body 为 `{ cmd, args }`，后端查**白名单**后调用同一套 service 函数，返回同一 JSON。

前端 `src/services/api/*.ts` 各文件只把 `invoke(...)` 换成 `call(...)`，视图层零改动。

白名单只收录四模块所需命令（示意）：

| 域 | 放行的 RPC |
|---|---|
| 收藏 | list_entries / list_entries_with_paths / create/update/delete_entry / batch_delete_entries / get_password |
| 小记 | notes 读写、note_lock 状态查询 |
| 验证码 | mfa 列表 / 生成 TOTP code（不放行增删改与显示密钥） |
| 文件 | file_shortcuts / url_paths 读写 |
| 公共 | settings 的只读子集（主题等）、auth 的**状态查询**（is_initialized / 是否已解锁） |

明确不放行：change_master_password、backup_*、cloud_*、fileshare（起子进程）、data 路径类、terminal、mfa 增删改。这些命令根本不进白名单，不是靠前端藏入口。

附件上传/下载走独立流式端点（`/api/attachment/{id}` GET/PUT），不走 JSON RPC。M3 前 web 端附件只读展示、不上传。

## 3. 认证：全自建（穿透层裸奔的前提下）

三层闸门，从外到内：

**3.1 服务闸**——"Web 访问"总开关，放设置弹窗「通用」面板，**默认关**。关时 HTTP 服务不监听，端口都不存在。开启时显示当前监听端口与状态二维码/链接（本机扫码即达）。

**3.2 登录闸**——Web 访问口令，与主密码**完全分离**：

- 开关首次开启时 App 内生成一个强随机口令，一次性展示、可重新生成；用户也可自定。主密码永远不会经公网传输，公网爆破面打不到主密码。
- 存储：`sha2 + 随机盐` 迭代散列（PBKDF2 式，复用现有依赖，无新密码学 crate）。
- 登录成功签发会话 token：HttpOnly + SameSite=Strict cookie，滑动过期默认 7 天，可一键吊销全部会话。
- 限速：同 IP 连错 5 次锁 15 分钟（参照现有 `unlock_attempts` 模式），错误响应不区分"用户不存在/口令错"（本就没有用户概念）。
- 可选加固（M4）：接自家 MFA 模块做 TOTP 第二因子——手机 desko 自己能生成码，不依赖外部验证器。

**3.3 数据闸**——web 会话能操作的范围跟随桌面解锁状态：

- App 处于锁屏（`master_key` 不在内存）时，web 所有数据 RPC 返回 `locked`，前端显示"设备已锁定，请在电脑上解锁"页。**不做 web 端输主密码解锁**——避免主密码走公网、避免 web 成为第二条解锁路径。
- 桌面端锁定/托盘锁定时，现有 `session_lock` 清 key 的同一动作里顺带吊销全部 web 会话。
- 小记同理会跟随 note_key 驻内存状态；需口令的小记条目在 web 显示"需本机解锁"。

## 4. 前端适配

- 入口判定：`!window.__TAURI_INTERNALS__` 即浏览器模式，transport 自动切 fetch。
- 登录页是 web-only 新增视图（一个口令输入框），不参与桌面端。
- 布局：手机竖屏下侧栏收起为顶部 tab，五栏内容单列化。默认小窗（1040×670）的桌面布局在平板/桌面浏览器直接可用，不做新设计稿，只做断点适配。
- 主题、锁屏态展示沿用现有令牌体系；web 端不出现备份徽标、局域网传输入口（依 feature 开关隐藏，复用现有"模块开关藏设置"机制）。

## 5. 安全清单

- 只绑 127.0.0.1；拒绝非本机 Origin（配 Allowed-Origin 白名单，用户填自己的域名）。
- SameSite=Strict cookie + 写操作要求自定义头 `X-Desko-Client`，挡 CSRF 与脚本直连。
- 不返回版本/banner；404 与未授权同形。
- 端口可配置，避免默认端口扫描特征。
- 登录成功/失败写日志（现有日志通道），失败含 IP 头（`X-Forwarded-For` 由穿透工具带入，App 内说明需穿透层开启该头）。
- HTTPS 由域名侧解决（穿透工具 TLS 或域前置的 Caddy/Nginx 反代 + 免费证书），App 不内置证书——文档写明。

## 6. 里程碑

- **M1 骨架**：axum 服务随"Web 访问"开关启停；`/api/rpc` 白名单 + 登录闸 + 锁态闸；四模块只读跑通。
- **M2 可写**：四模块增删改、get_password、附件只读展示；设置 UI（开关/口令/端口/会话吊销）；限速锁定。
- **M3 移动端**：竖屏断点适配、附件上传下载、验收截图流水线（dialog-shots 同款浏览器版）。
- **M4 加固**：TOTP 第二因子开关、穿透/HTTPS 部署文档。

## 7. 验收标准

1. 开关关 → 端口不通；开关开+错误口令 5 次 → 锁定生效。
2. 浏览器完成收藏增删改查、小记读写、验证码取码、文件路径跳转链接复制，全程手机竖屏可用。
3. 桌面端锁定后 3 秒内 web 全部数据请求变 `locked`。
4. `cargo check` 通过；e2e：现有桌面用例全绿（transport 改造不破坏桌面路径），web 冒烟用例走 Playwright 打 http 端点。
5. 白名单外命令经 `/api/rpc` 调用一律 403，有测试固定这一边界。

## 8. 已知取舍

- 不开机就不能访问——这是"本机常开"形态的固有代价（拍板时已选）。
- web 无长任务进度（备份等不进 web），无需事件流；将来若做实时同步再上 WebSocket。
- 单口令单"用户"，不做多账号；家庭共用场景届时再说。
