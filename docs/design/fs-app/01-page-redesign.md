# 局域网传输 · App 页改版方案

日期：2026-10-23　状态：**待拍板**（mock 已出，未动码）
mock：`design/fs-app-r1/mock-src.html` → `design/fs-app-r1/mock.html` → 10 帧（真 token）→ `design/fs-app-r1/shots/`
真机基线：`.tmp/fs-app-r1/current/`（纸/墨 × 停止/运行/收件/仅本机）

## 0. 结论

推荐 **A · 连接台**：上排左「投递卡」右「连接卡」双栏，下排整宽「共享文件夹」卡。服务起停、二维码、地址、口令状态全部收进连接卡一张；投递目标、拖投区、最近文件收进投递卡一张。B · 收发台（左文件夹栏 + 右一张工作台）作为对照一并出图，**不推荐**，理由见 §5。

页面一句话职责定死：**这台电脑开一个口子，手机扫码来收发文件**。所以首屏必须同时回答三件事——口子开没开（状态）、手机怎么连（二维码 + 地址）、文件落在哪（投递目标 + 共享文件夹）。现状这三件事散在横幅、页条、拖投卡、收件卡四处，且没有一件能一眼看完。

行为面一律不动：服务只手动启动、锁屏不停 sidecar、Origin/`Sec-Fetch-Site` 同站门不放宽、同名自动 `(1)`、单文件 4 GiB、口令与端口仍住设置弹窗页签。本轮**只改 App 页的骨架与文案**。

## 1. 现状与根因

`src/components/fileshare/FileShareModule.vue` 的问题不在配色，在结构：

| 项 | 现状 | 后果 |
|---|---|---|
| 状态说了三遍 | 页条 chip + `.banner-title` + 空闲面板 `.fs-idle-title` | 同屏互相重复，且哪一处都不带下一步 |
| 手机怎么连没有答案 | 只有一行 `.banner-url` 文本 | 用户要在手机上手输 `http://10.x.x.x:8000`，多数人放弃 |
| 警告是整宽横幅 | `.url-row.local` + 全宽警示条 | 抢掉首屏 1/4 高度，且与它要说明的那张卡分家 |
| 拖投卡与共享文件夹分家 | 两张卡中间隔着收件卡 | 「拖进来的文件去哪」要跨卡推理 |
| 投递目标藏在 chip 里 | 只有点进拖投卡才看得到 | 多目录时不知道会落到哪一个 |
| 收件行是裸 URL | `received` 渲染 `encodeURI` 后的整串 | 名字被 `%20`、路径前缀淹没，看不出是哪个文件 |
| 删除只在 hover | `.dir-del` 悬停才出现 | 触屏/键盘够不到；也让"能删"这件事不可发现 |
| 停止态半屏空白 | 空闲面板 + 拖投卡 + 收件卡叠在一起 | 首屏 40% 是空的，且没有一个主按钮 |
| 手输路径 | 添加文件夹是输入框 | 有原生目录选择器却不用 |
| 卡片语言 | 带边框的旧卡 | 工作区其他页早已是无框浮岛 + 发丝分行 |

根因：**这页是按"服务状态机"摆的，不是按"用户要办的事"摆的**。改版按三问重排。

## 2. 骨架 A · 连接台

```
顶栏（48 工作区壳，页条 Teleport 进来）  局域网传输 · [监听中]        ⚙
┌──────────────────────────────────────────┐ ┌───────────────────────┐
│ 投到 [ C:\Work\shared ▾ ]  同名自动加 (1) │ │ ● 运行中        停止  │
│                                          │ │ 手机扫码打开           │
│        （182px 拖投井，虚线）              │ │ 手机和电脑连同一个…     │
│                                          │ │      ▢ 156 QR ▢       │
│ 最近文件  共 40 个        📂 打开文件夹     │ │ [http://10.0.0.9:8000 ⧉]│
│ ─ 项目周报-2026W42.pdf      ⧉             │ │ ⊕ 端口 8000 · IP …    │
│ ─ 假期照片 093.jpg          ⧉             │ │ ⊙ 未设口令，同网段都能打开 设置│
│ ─ desko-src-backup.zip      ⧉             │ │ 文件只存在这台电脑上…    │
└──────────────────────────────────────────┘ └───────────────────────┘
┌─────────────────────────────────────────────────────────────────────┐
│ 共享文件夹  2  手机可浏览、可上传        ⌄ 展开另外 10 个   ＋ 添加文件夹 │
│ ─ C:\Work\shared  [投递目标]                        📂  🗑           │
│ ─ D:\share\docs                                     📂  🗑           │
└─────────────────────────────────────────────────────────────────────┘
```

三张卡，一屏装完，没有滚动。信息归属：

- **投递卡**（左，`minmax(0,1fr)`）：投到哪儿 → 怎么投（井）→ 投了什么（最近文件）。
- **连接卡**（右，300px 定宽）：开没开（状态点 + 停止/启动）→ 手机怎么连（QR + 地址）→ 谁能连（端口/IP、口令）→ 一句安心话。
- **共享文件夹卡**（下，整宽）：手机能看到哪些目录，每行的动作（打开 / 停止共享）。

服务起停**从顶栏搬进连接卡**：今天那颗 32px `.toggle-btn` 住在页条里（`FileShareModule.vue:240`），和"手机怎么连"隔了一张卡；搬进来后，停止态的「启动服务」正好落在解释它的那段话下面，运行态的「停止」落在状态点同一行。顶栏只留页名 + 状态 chip + 齿轮（齿轮仍开设置弹窗的局域网传输页签），不再放第二颗动作钮——一处动作只有一个入口，停止态也就不会出现"顶栏有启动、卡里也有启动"。

## 3. 状态矩阵（每格都有帧）

| 状态 | 标题栏 chip | 连接卡 | 投递卡 | 帧 |
|---|---|---|---|---|
| 运行中 · 同网段 · 无口令 | 绿「监听中」 | 真二维码 + 地址 + 黄字"未设口令，同网段都能打开 · 设置" | 井可拖，最近文件 3 行 | A1 |
| 运行中 · 已设口令 | 绿「监听中」 | 同上，口令行改灰字"已设口令，手机要先输 · 更换" | 同上 | A2（墨） |
| 已停止 | 灰「已停止」 | 虚线占位井 + 访问范围/口令两行 + **底部整宽「启动服务」**（主按钮） | 井改实线灰、文案"服务未启动，暂时不收文件"；列表空态一行说明，不显示"打开文件夹" | A3 |
| 运行中 · 仅本机 | 黄「仅本机」 | 锁占位井 + `127.0.0.1` + 黄字"本机拖投不受影响 · 关闭仅本机" | 井照常可拖（本机投文件不受影响） | A4 |
| 端口漂移（改过没重启） | 绿「监听中」 | 黄字"端口改到 8010，重启后生效 · 立即重启" | — | A5 |
| 窄窗 800×600 | 同上 | 双栏塌成单栏：QR 移到左，文字在右，页面纵向滚动 | 井收 104px | A6 |
| 投递目标下拉 | — | — | 浮层列出共享文件夹 + 勾选当前 + 「添加文件夹…」 | A7 |

`--warning-soft/--warning` 用于「仅本机」和一切"能用但达不到目的"的状态；绿只留给"手机现在真能连上"。现状把 localOnly 也画成正常态，是最误导的一处。

## 4. 硬账

壳与几何（与工作区其他页同档，1040×670 实测）：

| 项 | 值 | 依据 |
|---|---|---|
| 内容可用高 | 584 = 670 − 48 壳 − 16 − 22 | `--workspace-toolbar-height` + 内容 padding |
| 内容可用宽 | 920 = 1040 − 56 图标轨 − 32×2 留白 | `--workspace-gutter` |
| 上排卡高 | 416 | 投递卡 54 头 + 182 井 + 12 距 + 36 列表头 + 44×3 行 = 416；连接卡按 `measure.mjs` 逐帧核对，最满的一格（A1）不溢出、不裁行 |
| 下排卡高 | 136 = 48 + 44×2 | 恒定 2 行 |
| 页面合计 | 416 + 14 + 136 = 566 ≤ 584 | 首屏不滚动、不裁行，还剩 18px 余量 |
| 行档 | 文件行 / 文件夹行 44，双行文本 | 与行卡体系一致 |
| 控件档 | 28px `qbtn`/`sbtn`，主按钮 32px `pbtn`，图标钮 26px | 宿主弹窗 action-btn 档 |
| 二维码 | 156px 白底 + 8px 内白边，**永不随主题反色** | 扫码要黑白对比；墨底上白块是功能需要不是审美失误 |
| 地址框 | 32px `--sunken` + 等宽字 + 复制钮 | 与网页端 `.urlbox` 同方言 |

行数恒定（回答"几百条怎么办"）：

- 最近文件：**永远 3 行**，标题右侧「共 N 个」，出口是「打开文件夹」。第 4 条起不进页面，进资源管理器。
- 共享文件夹：**永远 2 行** + 「展开另外 N 个」；展开后卡内滚动（`scrollbar-gutter: stable`），不推走上面的卡。
- 井、连接卡、页条的高度与条数无关。

## 5. 为什么不推荐 B · 收发台

B 把共享文件夹升成左侧常驻栏（选中即"投递目标 + 手机浏览范围"），右侧一张大工作台装下连接、拖投、最近文件。它的好处是"文件夹是一等公民"，坏处有三：

1. **稀疏态空得离谱**：只有 1–2 个文件夹时，左栏 236px 全是空白（B1 帧可见），而 desko 的默认用户恰恰只共享一两个目录。
2. **一张卡干三件事**：工作台内部要两条发丝线切三段，卡高 584px，等于把"卡中卡"的债用分割线糊过去——这正是行卡体系明确禁止的方向。
3. **投递目标与文件夹栏重复**：井右侧还要再放一个目录选择器，两处指向同一个状态，改一处忘一处。

B 的价值在"共享目录特别多（≥10）且常切换"的重度用户。真要做，应当是 A 的下排卡加一个"展开成栏"的可选视图，而不是整页换骨架。

## 6. 实现范围（拍板后才动）

前端（`FileShareModule.vue` 重写模板 + 样式，脚本层小改）：

- 删除 `.banner-*`、`.fs-idle-*`、`.url-row.local`、`.drop-card` 一套；三张卡按 §2 重排。
- `received` 不再当数据源：改成 `recent` 列表（见下），字段 `name/dir/size/mtime`，渲染名字 + 「目录 · 大小 · 时间」双行。收件 toast 仍保留，但只负责"投好了"，不再充当文件列表。
- 添加文件夹改原生目录选择器：`@tauri-apps/plugin-dialog` 的 `open({ directory: true })`，`dialog:default` 权限已在 `src-tauri/capabilities/default.json:15`，无需新增能力。
- 「打开文件夹 / 在资源管理器中打开」走既有 reveal 方言（参照 `commands/note_lock.rs:409` 的 `reveal_note`）。

需要新增的原生面（**这是本轮唯一的后端活**）：

1. `fileshare_recent(limit) -> Vec<{ name, dir, size, modified }>`：直接复用 `fileshare-core` 的 `list_files` + `handlers.rs:299 page_entries` 的合并排序（全目录合并、mtime 倒序），不新增 HTTP 路由、不动 sidecar。理由：网页端是服务端渲染，今天**没有任何 JSON 文件列表接口**，App 要显示"最近文件"只能走命令层。
2. 二维码生成：仓库现在只有 `jsqr`（解码用），**没有生成器**。方案是前端加 `qrcode-generator`（MIT、无依赖、~10 KB）输出 SVG；不加 Rust 依赖、不请求任何外部服务。地址只在服务运行时生成，离线可用。
3. 端口漂移提示：`FileShareStatus` 已有 `configuredPort` 与 `boundPort`，两者不等即出"重启后生效"，**不需要新命令**。

不做：不改设置弹窗页签的表单（端口/口令/仅本机仍在那里）；不给网页端加接口；不动 sidecar 生命周期；不加自动启动。
