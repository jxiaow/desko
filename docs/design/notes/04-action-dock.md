# 小记动作排收敛与全屏阅读态落位

日期：2026-10-16　状态：**已实现**（拍板：全屏与置顶放出、收藏收进 ⋯）

## 1. 收敛前的毛病

| 面 | 收敛前 |
| --- | --- |
| 卡片 hover 排（未归档） | 全屏查看 · 编辑 · 置顶 · 收藏 · 导出 · 归档 · 复制正文 · ⋯ = **8 颗** |
| 卡片 hover 排（归档视图） | 全屏 · 编辑 · 取消归档 · 删除 · ⋯ = 5 颗 |
| 全屏阅读态 | 底部居中胶囊：置顶 · 收藏 ｜ 删除 · 编辑——首栏已住着「退出全屏 + 只读浏览」，动作却飘到视口底，既不属于纸面也不属于骨架栏 |

两个病根：同一时刻只有 1-2 个动作是用户要的，其余在抢注意力；置顶/收藏/复制正文 在归档视图的 ⋯ 里又出现一遍，同一动作两个入口。

## 2. 拍板结论

1. 卡片 hover 排一律 **4 颗**，两种视图同构：
   - 主列表：全屏查看 · 编辑 · 置顶 · ⋯
   - 归档视图：全屏查看 · 编辑 · 取消归档 · ⋯
   - 未解锁的加密条：解锁 · 导出（共 2 颗，那颗导出就是 ⋯ 组件的 `sealed` 形态）
2. 其余动作进 ⋯，一条规则贯穿：**排上占了哪颗开关，菜单只补另一颗**（`NoteMoreMenu.vue` 的 `archivedView` 一个 prop 表达完）
   - 主列表 ⋯：复制正文 · 收藏 · 归档 · 导出 ▸ · 加密 ·（重新锁定 · 解除加密）· 删除
   - 归档视图 ⋯：复制正文 · 收藏 · **置顶** · 导出 ▸ · 加密 · 删除
   - 全屏阅读态 ⋯：复制正文 · 收藏 · 归档 · 导出 ▸ · 加密 · 删除（置顶住在首栏，菜单不再重复）
3. 全屏阅读态 **删掉底部胶囊**，动作并进 54px 首栏右侧：置顶 · 编辑（唯一主按钮色）· ⋯。首栏是粘性的，动作比底部更常可见，正文下方还回一整条留白。
4. 书写态底栏 `NoteToolbar` 本轮不动。

## 4. 顺带修掉的第一击被吞

浮层侧栏（窄窗里叫出来的那一栏）原先挂在 `document` 的 `pointerdown` 上收起。收栏抽走整列宽度，同一次点击的 `mouseup` 就落到别的元素上：行尾那排钮（以及它下面的卡头）永远收不到 `click`，用户按下 ⋯ 只看到侧栏收起来。改成挂 `click`（捕获阶段，`railEl`/开关自身仍豁免）——动作钮先吃完这次点击，栏再收；`PopoverMenu` 的 `place()` 在同一个 flush 里读到的是收栏后的布局，菜单不会停在旧位置。

回归守卫：`NotesModule.test.ts`「收侧栏排在这次点击之后」——`pointerdown` 不收、`click` 才收。
